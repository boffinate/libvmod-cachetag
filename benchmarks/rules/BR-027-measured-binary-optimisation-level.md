# BR-027: The optimisation level of every measured binary is a cohort input

**Rule:** Record the effective optimisation flags of every binary on the measured path (`vinyld`, the VMODs, patched storage engines) in build provenance, and never report a performance figure from a binary built at `-O0` or with `-fno-inline`. A change to those flags is a new cohort ([BR-014](BR-014-hardware-cohorts.md), [BR-017](BR-017-harness-identity-invalidates-rows.md)); rows on either side of it are not comparable, and profiles from unoptimised binaries must not be mined for optimisation candidates because inlining changes which functions exist at all.

**Why:** On 2026-08-26 the benchmark harness was found to configure Vinyl with `--enable-debugging-symbols`, which `vinyl-cache/configure.ac` turns into `CFLAGS="... -g -O2 ... -O0 -g -fno-inline"`; gcc honours the last `-O`, so every `vinyld` in every cohort since the harness was written ran unoptimised while cachetag and xkey were built `-O2 -g`. Every published warm-hit, load and RPS figure, the 108k requests/s oha plateau, the 52 µs/hit Ryzen result and the cross-server ratios describe that binary. The 833-sample warm-phase profile that was to seed optimisation work showed `COM_DO_DEBUG` (a `static inline` one-liner) and `WS_Assert` as top symbols — artefacts of `-fno-inline`, not hotspots. The cachetag-versus-xkey comparisons remain internally fair because both VMODs shared the `-O2` policy, but cachetag's relative share of per-hit cost is understated against an `-O0` core. The compile lines were in every artifact's `build-commands.log`; nobody read them because the recorded `build_cflags=-O2 -g` field described only the VMODs.

**Comply by:** Using `BENCH_VINYL_BUILD_PROFILE=optimized` (the default since 2026-08-26: no `--enable-debugging-symbols`, explicit `CFLAGS="-O2 -g -fno-omit-frame-pointer"`) for every judged or profiled row; reading `vinyl_build_profile` and `vinyl_build_cflags` in `metadata.env`/`build-provenance.env` before comparing rows; treating `debug` rows as correctness or harness-diagnostic evidence only; and, when adding any new measured component, grepping its compile lines in `build-commands.log` for `-O0` or `-fno-inline` once before the first judged row.

**Tripwire:** Partial — the harness records `vinyl_build_profile`/`vinyl_build_cflags` in metadata and build provenance, and provenance verification refuses build-cache reuse across a profile change. The summarizer does not yet refuse to judge a `debug` row; until it does, the campaign plan must state the profile explicitly.
